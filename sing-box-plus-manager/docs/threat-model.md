# 威胁模型：PKI、认证分层与权限边界

> 本文是 [`../README.md`](../README.md) §4.1 / §4.2 / §4.8 / §4.9 的展开。
> PKI 与轮换部分参考组织内一套已在生产运行的同类系统；
> 应用层签名的参考实现位于 `shadowsocks-rust-plus/patches/0003-user-audit.patch`，
> 应用补丁后对应节点源码的 `crates/shadowsocks-auditd/src/export.rs`。

## 1. 信任边界回顾

```text
主控 ──mTLS + 应用层 HMAC──► proxy-manager-agent ──UDS──► 数据面
```

三条纪律（README §4.1）：主控绝不直连节点 UDS；agent 不解析快照 JSON；agent 不缓存快照。
本文补的是**这条链路上的身份与密钥怎么管**。

## 2. PKI 分层

### 2.1 结构

```text
离线 root CA                      只签 intermediate，私钥不出离线 workspace
└─ 每节点 / 每 generation
   ├─ server intermediate CA      该节点专属
   ├─ client intermediate CA      该节点专属
   ├─ server leaf / client leaf   固定 SAN，EKU 单一
   └─ deployment/                 节点只取这一层的最小材料
```

**每个节点有自己的一对 intermediate**，不是全网共用一个。这样吊销一个节点不牵动其他节点。
generation 用日期 + 序号命名（如 `<日期>-a`），轮换时新旧 generation 并存一段时间。

签发时离线校验：SAN 精确匹配、EKU 单一（server leaf 只有 `serverAuth`，client leaf 只有
`clientAuth`）、key 与 cert 匹配、serial 唯一、部署文件集最小、权限正确。
**这些校验必须在签发阶段完成**，因为运行时不一定有能力再做一次——见下。

### 2.2 在线信任的是精确 leaf，不是 intermediate

这是最反直觉、也最容易被简化掉的一条。

许多 TLS 实现**没有「期望对端 SAN 等于某字符串」的独立 matcher**：它们会验证证书链，
但不会按配置去比对对端 SAN。如果授权 bundle 里放的是 intermediate，
那么**任何由该 intermediate 签出的证书都能握手**——包括不该被信任的那些。

因此：

1. 离线签发阶段精确校验 SAN 与 EKU；
2. 把**那一张 leaf 本身**作为对端的信任锚放进授权 bundle；
3. 需要时把 intermediate 的 Subject 设成与预期 leaf 的 Subject 一致，
   使标准客户端的证书选择器能匹配到并发送配置的完整链——但**对端并不信任该 intermediate**。

必须诚实地写明：**这实现的是运行时精确证书授权，不是运行时逐字符串比较 SAN。**

并加一条护栏：**调整签发器或证书 Subject 后，必须重跑真实组件的正负矩阵，
不能只做链验证。** 链验证通过不代表那个实现的选择逻辑还成立。

### 2.3 吊销的实质

证书上的 `REVOKED` 标记**只是离线审计记录**，不会让任何在线组件拒绝谁。
真正的在线吊销动作是：**把旧 leaf 从授权 bundle 里移除**，让对端在 reload 或重启后拒绝旧证书重连。

三阶段流程，顺序不能反：

1. **overlap**：主控的 server bundle 同时含新旧 intermediate；节点的授权 bundle 同时含新旧 leaf。
   **先节点后主控** reload——反过来会在切换窗口里把自己关在门外。
2. **换叶**：各自切到新 leaf，重建链路，确认全部健康。
3. **revoke**：bundle 里只留新的那份。

窗口内暂停采集，在途请求失败后不重试不重放（`operations.md` §3.1）。

### 2.4 私钥与巡检

- root 与全部 intermediate 私钥留在**离线 workspace**；节点只拿到自己那份部署材料。
- 证书到期巡检**只读公钥叶子**。为此把祖先目录设成可穿越但不可列举、被巡检的公钥设成可读，
  **私钥权限不变**。
- **绝不为了让巡检能读而把采集身份加进持有私钥的组**——那等于抹掉 C18 想保住的分界线。
- 巡检输出不得包含 PEM、私钥或证书主题；阈值分两级（如 30 天 warning、7 天 critical），
  缺失 / 损坏 / 未生效 / 已过期一律 critical。

### 2.5 密钥不进版本库——用门禁，不用嘱咐

> 同类系统的 PKI 文档明确写着「该目录及其备份不得进入 Git」，
> 实际却有 118 个文件被跟踪，包括离线 root CA 私钥与发布签名私钥，
> 且没有任何忽略规则覆盖它们。

本项目建 PKI 的**第一步**是写 `.gitignore` 与提交前校验，第二步才是生成密钥。
顺序反了就会重演同一件事。

## 3. 应用层 HMAC（D12）

**传输层 mTLS 只提供通道，不能替代每节点独立的应用层签名。**

- 每节点一把独立 HMAC key（32 随机字节）。
  **不得复用**任何 CA 材料、发布签名密钥或数据面 PSK。
- 签名覆盖 canonical 化的请求与响应（方法、路径、节点标识、时间戳、nonce、body 摘要），
  编码要**长度明确**，不用字符串拼接。
- 带 **nonce 重放缓存**（参考实现用 600 秒）与**时间戳偏差窗口**（参考实现用 300 秒）。
- 常量时间比较；重复或畸形的签名 header 直接拒绝。
- **先验响应签名，再解析响应内容**——顺序反了等于先信任后验证。

收益具体在两处：

1. 若将来在节点侧插入 C18 允许的那种反代，mTLS 会在反代处终结，
   **只有应用层签名还能证明「这份快照来自这个节点」**。
2. 凭据映射出的节点是**授权真相**，payload 里的 `node_id` 只用于交叉校验——
   不能让请求自己选择归属。

如果将来审计链路（README §4.8）也走同一条传输入口，必须：
**不同 UDS、不同 handler、不同用户组、不同 HMAC key**。共用通道不等于共用身份。

## 4. 权限边界

### 4.1 两个 socket 不许合并（C18）

快照 socket 是只读档，配额 socket 是写档。配到同一个组上就抹掉了这条分界线。
落地形态见 `operations.md` §1.4：agent 需要**主组 + 补充组**。

### 4.2 最小权限身份

- agent 与数据面同机**不同 uid**；
- 各服务用专用的、锁定密码、无登录 shell 的系统账号，不复用共享 web 身份；
- 需要特权能力时只授予**单一 capability**（例如只给网络管理能力），不给 root、不给 sudo；
- systemd 侧限制写路径、设备、namespace、地址族、系统调用、内存与任务数。

可参照 `shadowsocks-rust-plus/packaging/*.service` 的硬化项。

### 4.3 残余风险要写出来

任何一层隔离都有边界。同类系统在文档里明确写出了「已经进入某个 cgroup 的恶意进程仍可
自行提交请求参数」这类残余风险，而不是声称边界是密封的。本项目沿用这个写法：
**把隔离挡不住的那部分列出来**，比宣称没有残余风险更有用。

## 5. 审计链路的独立性（C24）

- 审计的保留期与对外声明**独立于计费链路**制定；D19 已取消独立审计角色，管理员具有全权。
- 管理员代查用 `/users/{id}/audit/access`，仅 `admin` 可用；`admin / user` 均可用 `/me/audit/access`
  查询本人，目标由服务端会话确定，不接受客户端用户 ID、身份或路径。两端点均须开启全局审计。
- 每条访问记录以 `node / run / in / user` 关联已批准的完整 lineage，先核验历史用户归属再裁剪时间窗；
  文件名不作为授权依据。关联不唯一、字段缺失、归属不明及 `clock_ambiguous` 的记录不返回（C35）。
- 每页重验会话、角色、全局开关与归属；cursor 绑定调用者、目标和时间窗。**拉取行为本身落主控审计**，
  按一次查询聚合留痕、每页限频，与被拉取的数据分表存；完整错误语义见 README §4.8。
- 节点采集含连接字节量与时长，个人响应只返回展示字段；页面不展示不代表节点未采集。
- 日志里只记批次 ID、节点公开标识与错误码，
  **不记密钥、完整原始快照、身份明细或签名 header**。
- 节点上的审计文件在第一版**不承诺防 root 篡改**——诚实标注，不要让下游误以为它是证据级的。

## 6. 会话与 OAuth

详见 README §4.9。此处只重复三条最容易被简化掉的：

1. **匿名伪造的回调不创建会话、不写数据库**，否则登录入口就是免认证的写放大入口。
2. 授权码换取身份**成功之后**才消费 `state`（墓碑哈希，原子），失败不消费。
3. **授权结论每请求重新求值**（D13），历史角色只留痕。每请求同时检查会话撤销与成员事实 TTL。
   本地禁用/规则变更在下一个请求生效；上游离职/转岗须刷新最小成员事实才能感知，默认 TTL 60 秒。
   过期刷新失败即拒绝受保护请求，发现离职撤销全部会话；平台自身传播延迟单独披露。
   可缓存规则文件内容和 TTL 内成员事实，**不能缓存最终授权结论或继续使用过期事实**。
