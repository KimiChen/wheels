新用户怎么开通

首次用泡游账号登录时自动从账号池领一个计费身份，并签发一条订阅—— 没有「选哪几个节点」这一步：一个身份在全部入口上通用， 每个节点拿到的都是「这个人本月还剩多少」的同一个数。 池子空了时登录仍然成功，但订阅里不会有能用的节点，本人页面上会说明原因。

退役身份、补开通、改档位目前只有命令行： proxy-manager user retire / grant / tier。

额度分四档，每个人属于其中一档（定案第三条）

档位的字节数与「谁在哪一档」都是数据库里的权威值，这一页只读。 改档位走 proxy-manager user tier，调低要按 D21 先预览再确认。 改动对本周期立即生效——额度是参数，账本记的是用量， 「剩余 = 档位字节数 − 本周期已用」跟着重算即可。 调高不会让已经断掉的连接自己回来，节点侧只是重新允许新连接。

四档额度
还没有档位

单位是十进制 TB（1 TB = 10¹² 字节），不是 TiB—— 与客户端流量条上那个数同一个口径。 超出后新连接被拒；已建立的连接仍受剩余额度约束直到结束。

默认档位 —。 每个节点拿到的是「这个人本月还剩多少」的同一个数（镜像下发）， 不按节点拆分——拆分会让一个人把流量压在单一节点时， 在四分之一额度处就被切断。

展示时区 —。 账本的时刻是 UTC，而月界按 UTC+8——2026-09 这个周期的起点是 2026-08-31T16:00:00Z。写成 UTC 零点的话， 每个月头 8 小时的用量会算进上一个月，而那只有对账时才看得出来。

每一轮先采集入账，再按已结算的用量算额度，最后整表下发—— 顺序是结构上保证的，不是靠调用方自觉。 每次采集恰好产生一个已结算序列，每次正额度下发恰好消耗一个。

节点 startup_action / stale_action

按节点配在 nodes.toml 的 [node.quota_control] 里， 不是全局设置。节点侧默认是 allow：重启后尚未收到配额表就无限放行。 配成非 deny 时，同一段里必须写下 fail_open_acknowledged（一句理由），否则主控拒绝启动—— 让这个取舍留下签字，而不是埋在一行配置里（C12）。

首快照策略

同样按节点配，没有默认值：缺省即启动失败（C8）。 baseline 只建基线、首次增量为 0；include 把节点上已有的累计一次性记成首次增量。当前各节点的取值在 节点页上。

这一页与计费设置无关

审计保留期与数据范围单独说明。管理员可按用户查看；普通用户在审计启用时可查看自己的出站目标。 记录按文件大小归档，归档时间不固定。
