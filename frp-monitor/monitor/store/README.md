# SQLite 历史与节点网卡流量

本包独立于 FRP 转发逻辑；`Accept` / `AcceptProbe` 只复制有界样本到内存队列，
不会等数据库。`Open` 建立 SQLite WAL 和 schema v1；数据库及 sidecar 必须是
0600 普通文件，专属父目录必须为0700，路径祖先不能是符号链接。目录和新数据库
会自动按私有权限创建，既有公开文件会拒绝打开。请将库放在本机文件系统中，不能
将 WAL 数据库放在网络共享文件系统上。

`modernc.org/sqlite v1.59.0` 使用纯 Go 的 SQLite 3.53.4，支持
`CGO_ENABLED=0` 下的 Linux amd64/arm64；`modernc.org/libc` 按其官方 go.mod
锁定为 `v1.75.7`。相应 FRP 模块补丁为 `patches/0002-sqlite-dependency.patch`。
升级时需同时核对 libc、schema 与 WAL 回归测试。许可来源和原文在 `licenses/`，
发布包应附带整个目录。

## 聚合和接口

- `Open(Config{Path, RetentionDays, ReportInterval})`：默认保留7天，允许1～31天；
  报告间隔默认1秒，允许1秒～1小时。在线状态不入库，重启后应由 monitor 重新握手。
- `Accept(node, receivedAt, metrics)` / `AcceptProbe(node, task, receivedAt, latencyMS)`
  返回是否进入队列；只使用服务端接收时间，指标均值只收 `quality=ok` 的值。
  探测延迟允许0～900ms，`-1` 表示失败。任务键由上层绑定任务ID与目标，不能混用。
- 每分钟在一个事务中写入累加和、有效样本数、覆盖秒数、探测摘要、流量基线及日增量。
  `Flush(ctx)` 显式刷入此前已接受的事件；`Close(ctx)` 停止接收、排空队列并刷盘，
  调用者超时只终止等待，worker继续在有界数据库期限内收尾。
- `History` / `ProbeHistory` 返回已落盘数据，最新内存样本最多延迟一个刷盘周期。
  查询范围最多31天，按整分钟对齐并自动扩大步长，返回不超过500点。
  空时间桶保留 `null` 和0个样本；指标分别计算有效样本数和覆盖时间，不能把
  无效 CPU 当成0，也不能将一分钟最后一个样本充当平均值。
- 整数累加和使用任意精度整数，均值向下取整并以十进制字符串返回；浮点观察用
  有理数累加后取均值，避免负载累计溢出。降采样累加和与样本数一并合并。
- 覆盖时间按实际相邻接收时间计算，每个样本最多贡献一个报告间隔；第一份样本
  贡献一个间隔（最多60秒），重复/加速上报不能虚增持续覆盖。覆盖不等同于可用率。

## 流量口径和恢复

流量来自有效的网卡累计计数器差值，与页面速度积分、FRP隧道流量分别计量。
`scope + boot_id + iface` 共同确定计数范围，`boot_id` 已包含采集器的网卡集合摘要。
首份观察只建基线；启动标识、scope、网卡集合或选择变化，以及任一方向计数回退，
整对收发计数均重新建基线。读取失败不覆盖基线。不同WSS会话和monitor重启可
延续落盘基线，基线本身不代表节点在线。

`Traffic(node, at)` 返回服务端UTC指定日的已观察字节数、覆盖秒数和重建次数。
没有有效计数器对时字节数是 `null`；真实零增量返回字符串 `"0"`。
跨UTC日的一次差值全部归入第二份观察的接收日，因此跨日或长断线存在归属误差，
不宣称自然日完整账单。流量覆盖对每对观察最多记两个报告间隔，以揭示长断线缺口。
日记录按完整UTC日保留，避免在当天中午清理掉保留边界当天的数据。
基线与增量在同一事务更新，失败全部回滚，重试不重复累计；崩溃可能丢掉最近一分钟
历史，但同一计数范围下下一份累计值可从持久基线补回字节差值。

## 有界与故障行为

队列默认4096条（可设1～65536），内存待写桶总数上限16384，采样节点上限1024。
待写桶达到上限时新观察均丢弃，直到一次成功刷盘；不强迫转发线程等待磁盘。
全量查询、写入事务分别有3秒期限，SQLite busy timeout为1秒。
持久化使用 `synchronous=FULL`；正常退出刷盘，WAL在下次打开时恢复。
SQLite磁盘用量随节点、探测数和保留期增长，本实现未宣称大规模容量验收。

`Status` 返回队列深度、丢弃数、写入/查询错误数以及固定错误类别，错误不会泄露路径。
发生丢样、磁盘错误、数据损坏或worker panic后 `degraded` 保持为true，以免隐藏历史
缺口；新数据可以继续重试写入，重启后统计重新开始。坏数据库及未知schema拒绝打开，
上层必须保留实时功能并展示存储降级。数据库不含token、密钥、主机IP或资产事实。

验证覆盖真正平均、字段缺失、覆盖时间、整数极值、断线空点、降采样边界、UTC跨日、
重启/网卡/计数回退、读失败、事务回滚、队列满、并发关闭、保留清理、权限、未知schema、
损坏记录以及子进程不Close直接退出后的WAL恢复与 `integrity_check`。
