# 安全政策

`sing-box-manager` 管理代理凭据、CA 私钥、订阅 token 和远端部署，因此安全问题应优先私密处理。

## 支持版本

项目目前处于首个公开预览版本，只对最新发布版本提供安全修复。旧预览版本不承诺维护。

| 版本 | 安全更新 |
|---|---|
| `0.1.x` 最新发布 | 支持 |
| 更早版本或未发布提交 | 不保证 |

## 私密报告

请优先使用 GitHub 仓库的“私密漏洞报告 / Security Advisories”功能（若仓库已启用）。
如果该功能不可用，请通过仓库所有者公开资料中提供的私密联系方式联系维护者。

不要在公开 Issue、讨论、Pull Request、聊天截图或 CI 日志中披露：

- 漏洞利用步骤和可用 PoC。
- 真实服务器地址、SSH 用户或网络拓扑。
- `ENCRYPTION_MASTER_KEY` 或历史主密钥。
- CA/Agent 私钥、enrollment 文件。
- Shadowsocks PSK、VLESS UUID、Landing 凭据。
- 订阅 token 或完整订阅 URL。
- 含秘密的 SQLite、WAL、配置 artifact 或日志。

## 报告内容

请尽量提供：

- 受影响版本或提交。
- 受影响组件：CLI、Controller、Agent、PKI、编译器、订阅、计量等。
- 前置条件和最小复现。
- 实际影响，包括是否可读取秘密、越权部署、重复计量或中断数据面。
- 已知缓解措施。
- 脱敏后的日志或测试。
- 是否已经向第三方披露。

请使用占位符替换所有真实基础设施信息。

## 处理方式

维护者会尽力：

1. 确认收到报告。
2. 复现并判断影响范围。
3. 与报告者协商披露时间。
4. 在修复可用后发布安全说明和升级步骤。

这是社区预览项目，目前不承诺固定响应 SLA。若漏洞正在被主动利用，请在标题中明确标记紧急性。

## 威胁模型边界

项目重点保护：

- 数据库被单独窃取时的秘密机密性。
- Controller 与 Agent 之间的双向身份。
- 配置 artifact 的完整性和部署顺序。
- 命令重放、流量重复计量和重启结算。
- 订阅 token 的不可逆存储。

不直接保证：

- sing-box 本体或代理协议自身的安全。
- 已获得 Controller 主机 root 权限后的秘密机密性。
- 管理员主动提交恶意配置。
- SSH、反向代理、操作系统和云防火墙的正确配置。
- 多 Controller 并发写同一个 SQLite。

完整分析见 [威胁模型](docs/threat-model.md)。

## 临时缓解

怀疑泄露时：

1. 停止公开订阅和 Controller 外部入口。
2. 吊销受影响 Agent。
3. 保存取证副本，不要破坏 SQLite/WAL 和日志。
4. 轮换订阅、PSK、证书和主密钥。
5. 在确认 re-seal 完成前保留历史主密钥。
6. 检查审计、部署和流量批次是否异常。

主密钥和证书恢复步骤见 [故障恢复](docs/disaster-recovery.md)。
