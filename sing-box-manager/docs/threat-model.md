# 威胁模型

本文覆盖 `sing-box-manager` 的 Controller、Agent、声明式配置、状态库和订阅服务。sing-box
数据面及 Shadowsocks、VLESS 等协议自身的密码学安全不在本文范围内。

## 安全目标

- 未授权用户不能改变期望状态、下发配置或读取订阅凭据。
- 数据库、日志、审计记录和 Git 历史中不出现明文业务密钥。
- Controller 只向已登记的 Agent 下发命令，Agent 只接受已固定身份的 Controller。
- 配置发布可验证、可回滚、可幂等重试。
- 单个 Agent 离线或 Controller 重启不应立即中断已经运行的数据面。

## 需要保护的资产

| 资产 | 保护要求 | 保存位置 |
|---|---|---|
| `ENCRYPTION_MASTER_KEY` | 机密性、可恢复性 | 仅环境变量或受限环境文件 |
| Agent CA、客户端 CA 私钥 | 机密性 | 状态库中的信封密文 |
| Shadowsocks PSK、VLESS 私钥等业务密钥 | 机密性 | 状态库中的信封密文 |
| 编译后的 sing-box 配置 | 机密性、完整性 | 加密制品；部署时经 mTLS 传输 |
| 订阅令牌 | 机密性 | 数据库仅保存摘要，明文仅在创建时返回 |
| Agent enrollment 文件 | 机密性、完整性 | Agent 主机本地受限文件 |
| 流量、部署和审计数据 | 完整性 | Controller SQLite 状态库 |

## 信任边界

### 本机管理边界

`plan`、`apply`、`status`、enrollment 和密钥轮换命令直接访问本地配置、环境变量和
SQLite，不提供公网管理 API。管理员认证依赖操作系统账号、文件权限和 SSH 管理边界。

### 订阅与探针边界

Controller 默认监听 `127.0.0.1:9736`，生产路由只有：

- `/sub/{token}`
- `/healthz`
- `/readyz`
- `/metrics`

公网反向代理只应转发 `/sub/*`。订阅令牌等价于用户凭据，必须通过 HTTPS 传输。健康检查和指标应保持
在回环或受信监控网络中。

### Controller 与 Agent 边界

Agent 默认监听 `0.0.0.0:39736`，双方通过 mTLS 建立信任：

- Controller 校验 Agent 的证书链和 `host_id` 身份。
- Agent 校验 Controller 客户端证书，并固定允许的客户端身份。
- Controller 不下发任意 shell；Agent 只执行协议内定义的部署、回滚、状态和计量操作。
- 命令带有幂等标识，重复请求不会重复产生副作用。

### SSH 引导边界

当前版本仍由管理员通过 SSH 安装二进制、enrollment 和 systemd 单元。SSH 凭据只用于引导，
不会写入公开示例或状态库。应关闭密码登录、限制来源，并单独保护部署密钥。

## 主要风险与缓解措施

| 风险 | 当前缓解 |
|---|---|
| 未授权修改期望状态 | 不开放管理 API；限制配置、数据库和环境文件权限 |
| include 越界或配置注入 | TOML 拒绝未知字段；include 只接受同目录安全文件名；跨文件引用严格校验 |
| 数据库被复制后泄密 | 业务密钥和配置制品使用主密钥信封加密 |
| 运行主机被完全控制 | 视为信任边界失守；使用最小权限账号、主机加固和独立备份降低影响 |
| 假冒 Controller 或 Agent | mTLS、证书链校验、主机身份绑定和客户端身份固定 |
| 命令重放 | 命令标识和 Agent 端幂等存储 |
| 非法 sing-box 配置 | 编译前拓扑校验，部署前执行 `sing-box check`，失败不切换活动版本 |
| 部署中断 | 分阶段部署、状态持久化、可重试和最近版本回滚 |
| 订阅令牌泄露 | 高熵随机令牌、数据库只存摘要、HTTPS、响应禁止缓存 |
| 日志泄露密钥 | 诊断输出默认脱敏；公开问题报告要求再次人工检查 |
| 多 Controller 并发写库 | 明确限制为单 Controller、单 SQLite 写者 |

## 残余风险

- 主密钥和所有可用备份同时丢失时，加密业务数据不可恢复。
- Controller 主机被完全控制时，攻击者可读取运行时主密钥并接管控制面。
- 订阅令牌一旦从客户端或反向代理日志泄露，在令牌轮换前可被冒用。
- 当前自动部署只支持 Shadowsocks 入口；VLESS-Reality 可被编译和保存，但尚未进入远端部署闭环。
- Agent 进程异常退出时，sing-box 子进程的处置依赖服务管理器；生产 systemd 单元必须使用
  `KillMode=control-group`，Agent 重启后会恢复已记录的活动版本。
- SQLite 是单机状态库，不提供多活和分布式锁。
- 流量计量依赖数据面累计值；带外修改或绕过 Agent 管理 sing-box 可能造成偏差。

## 运维要求

- 配置、`.env`、数据库、enrollment 和备份文件权限设为 `0600` 或等效权限。
- 主密钥与数据库备份分开保存，并定期演练恢复。
- 不在 Git、工单、聊天或 CI 日志中粘贴真实 IP、域名、令牌、证书和密钥。
- 只开放必要端口；Agent 端口只允许 Controller 访问。
- 定期检查证书到期、Agent 在线状态、失败部署、磁盘空间和备份新鲜度。
- 升级前先阅读 [更新日志](../CHANGELOG.md) 和 [故障恢复](disaster-recovery.md)。
