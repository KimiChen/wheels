Prose

数据资产的登记口径

正文层只负责 运行文本，不引入组件类名：把 .wsk-prose 放在容器上，其中的标题、列表、引用、表格、 图片与代码都会自动取到令牌。适合 Markdown 渲染结果直接落进来。

  • 字段级血缘必须可追溯到上游系统。

问答 已解决

服务端渲染 + HTMX，片段替换后事件全失效

ZY
周予
 发布于 6 小时前 18 回复 1,276 浏览

页面是服务端渲染的，交互靠 HTMX 换片段。第一次加载一切正常，但只要 hx-swap 换过一次内容，那一块里的按钮就全点不动了。

现象

控制台没有任何报错，元素也在 DOM 里，querySelector 拿得到——就是没有反应。现在只能在每次替换后手工重绑： 

// 每次换完片段都要重来一遍，而且很容易漏
document.body.addEventListener("htmx:afterSwap", () => {
  initMenu();
  initTable();
  initDialog();
});

为什么会失效

因为监听器绑在元素上，不是绑在事件流上。片段替换会把 旧节点整个丢掉，连同挂在上面的监听器一起。新节点是全新的对象，没人给它绑过 任何东西。

换句话说：加载时绑定的写法，隐含了一个「DOM 不会被替换」的假设。服务端 渲染 + 片段替换恰好打破这个假设。

下面这几种写法都带着同一个假设：

  • getElementById(...).addEventListener(...)
  • querySelectorAll(...).forEach(el => el.addEventListener(...))
  • 在模块顶层缓存节点引用，例如 const region = document.getElementById("toast-region") ——节点被换掉之后，往里写就是往游离节点里写

做法：把监听下沉到 document

事件会冒泡到 document，而 document 永远不会被片段替换换掉。所以只绑一次，用 closest() 判断这次点的是谁： 

function on(type, selector, handler) {
  document.addEventListener(type, (event) => {
    const target = event.target instanceof Element
      ? event.target.closest(selector)
      : null;
    if (target) handler(event, target);
  });
}

// 绑一次，之后换多少次片段都不用管
on("click", "[data-dialog-open]", (event, button) => {
  document.getElementById(button.dataset.dialogOpen)?.showModal();
});

两种写法的差别：

维度 加载时绑定 document 委托
片段替换后 失效，需重绑 照常工作
同页多实例 固定 id 只支持一个 按属性匹配，天然支持
监听器数量 随元素数量增长 每类事件一个

替换之后还需要做什么

事件不用管了，但初次渲染还是要做——标签同步、分页按钮、 首屏要显示第几页，这些新节点不会自己算出来。所以留一个幂等的入口： 

document.body.addEventListener("htmx:afterSwap", (event) => {
  wsk.mount(event.target);
});

状态放在 dataset 上而不是闭包里，元素被换掉时状态自然重置， 也方便直接用 F12 看当前值。
